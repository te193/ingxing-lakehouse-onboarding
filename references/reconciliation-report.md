# 第5步精简对账报告

完成实际只读查询后，默认直接在当前会话按本模板输出，不生成文件。仅当用户明确要求时，才保存 Markdown 或 SQL。

## 默认输出

```markdown
当前步骤：第5步—数据对账

结论：通过 / 条件通过 / 不通过 / 未完成
范围：业务日期=...；MaxCompute=...；MySQL=...；快照=一致/同日近似/不可比

| 指标 | MaxCompute | MySQL/理论值 | 差异 | 结果 |
|---|---:|---:|---:|---|
| 数据量 | ... | ... | ... | 一致/异常/N/A |
| 业务键去重数 | ... | ... | ... | 一致/异常/N/A |
| 空业务键 | ... | ... | ... | 一致/异常/N/A |
| 其他关键指标 | ... | ... | ... | 一致/异常/N/A |

说明：未发现异常 / 简要说明差异及快照限制。
下一步：无需处理 / 修复后重跑 / 补充权限后重查。
```

`其他关键指标`只选择当前接口真正需要的一项，例如子记录数、理论展开数、重复技术 ID 或维表未匹配数；不要为了填满模板增加无意义指标。差异同时需要百分比时，合并写在一个单元格中，例如 `+12（0.35%）`。

## 结论规则

- `通过`：两边属于同一快照边界，必查指标全部符合预期。
- `条件通过`：采集时点不同，但差异已量化并有合理业务解释。
- `不通过`：发现漏数、重复、空键、父子关系或维表匹配等实质异常。
- `未完成`：必要连接不可用、权限不足或两边无法形成可比较边界。
- 不适用或无法取得的指标写 `N/A`，不得用 `0` 冒充。

## 异常时展开

默认简表后只追加与异常有关的内容：异常指标、原因判断、有限条代表性样本和修复建议。正常通过时不要附加长篇查询过程、完整 SQL 或逐字段明细。

如果连接失败，明确数据源和失败类型，并将结论写为 `未完成`；可以提供回退 SQL，但不能宣称已经完成对账。
